# Changelog

All changes below are unreleased. No deployment or publication is performed.

## [Unreleased]

### Added

- Trusted pure Dart outcome compiler and source-drift checks, an operator-pinned
  server certificate catalog, and atomic finite-path cure rewards with durable
  replay verdicts, per-case eligibility, cooldown and rolling-window caps.
- Certified, unrewarded and unproven results are explicit in the app. Encrypted
  account/origin-scoped queues preserve signed receipts and their original
  verdicts across restart without crediting local practice progression.
- Bounded local retention and account erasure, legal-hold protection, permanent
  replay fences, and an fsynced external erasure journal with real old-backup
  restore/reapply acceptance. No production cleanup scheduler is enabled.
- Pinned local PostgreSQL backup/restore, HTTP load and startup gates, bounded
  metrics/admission, and retained three-model latency/quality evidence.

- Authenticated local HTTP control-plane composition, durable identity/session
  and device-key storage, browser code exchange, and a real Dart-to-Go-to-
  PostgreSQL signed-receipt/reconciliation integration gate.
- Resolved CycloneDX dependency inventory and CI drift checks, installed-license
  classification, native-commit/Pub/Go vulnerability coverage, and real planted
  secret, vulnerable-version and incompatible-license acceptance tests.

- Bounded mechanical solvability search returns a replayable winning action
  sequence and distinguishes exhausted search budgets from proven success.
- Local PostgreSQL integration and race tests cover receipt retries,
  authorization, audit integrity, migration rollback, and concurrent boot.
- Explicit model-free contract verification and strict real-model acceptance
  commands, plus a pinned project-local Go vulnerability scanner.
- Durable local-practice career results, equipped-action checks, and structured
  session recovery with exactly-once completion and visible terminal results.

### Fixed

- Dialogue correction attempts now use validated shared configuration (0–2,
  default 2) in production session bindings and model measurement tools. Zero
  disables corrections while retaining the validated-output fallback.
- Native model loading fails visibly for missing or invalid real weights;
  development stubs require explicit selection. Native builds use the pinned
  llama.cpp API and preserve relocated legacy build caches.
- Inference cancellation stops active generation, disposal waits for teardown,
  repeated prompts reuse valid logits, and statistics come from the active model.
- Calm cases can finish successfully when session progress reaches its target;
  headless scripted replay stops at the first terminal result.
- App startup resolves the configured bundled manifest through its actual asset
  key. Progression settings are available through the shared configuration.
- Download and inference share the selected model's verified cache path. Required
  clues are validated before dialogue is sanitized, with bounded fallback.
- Interrupted downloads preserve validated ranges and ETags; queued cancellation,
  disk exhaustion and corrupt resume metadata fail safely. Prompt corrections
  retain length/list/clue checks and use a bounded fallback on correction overflow.
- Checkpoint writes serialize across instances and reject retired-controller
  saves. Empty loadouts are recoverable without replacing a valid saved loadout.
- Format checks leave source files unchanged and propagate failures. Content
  checks accept the canonical taxonomy registry while rejecting banned content
  and missing input directories. Scanner failures no longer pass as clean scans.

### Security

- Typed client transport policy bounds HTTPS origins, loopback development,
  timeouts, retries, response/queue sizes and browser callback registration.
- Secret scans cover both staged and working bytes with redacted findings;
  narrow fixture exceptions cannot hide a planted credential.
- The privacy gate exercises actual client and PostgreSQL persistence instead
  of searching comments for the word transcript. License attribution now matches
  the exact model candidates and records target-build notice/source obligations.

- Receipt retries, profile changes, idempotency records, and acceptance audit
  writes share an atomic database transaction. Device signatures alone do not
  grant ownership, a valid lease, card inventory, or session authorization.
- Receipt schema 0.3 alone cannot prove terminal gameplay. The server holds
  unmatched outcomes and accepts reward authority only from a trusted pinned
  compiler path; client-supplied ledger payouts remain rejected.
- Recovery persists structured gameplay state without raw dialogue. Oversized
  career saves fail before replacing the last readable save.
